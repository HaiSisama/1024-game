# 1024 小游戏设计文档

日期：2026-08-17
状态：已与用户逐节确认

## 1. 项目概述

一个基于 HTML + CSS + JS 的单文件网页小游戏（1024 变体）。玩家通过方向键或触摸滑动移动数字方块，相同数字相邻合并为两者之和，目标是拼出 1024 方块。

核心规则（来自需求）：

1. 网格 4x4 或 5x5，方向键或滑动屏幕控制所有方块向同一方向移动
2. 相邻且数字相同的方块合并为一个新方块，数字为两者之和（2+2=4，4+4=8）
3. 每次移动并合并后，在空白格随机生成一个新方块
4. 胜利目标：拼出数字为「1024」的方块

## 2. 已确认的需求决策

| 决策点 | 结论 |
|---|---|
| 网格大小 | 4x4 与 5x5 都支持，界面可切换；切换即新开一局 |
| 新方块生成 | 2（90%）/ 4（10%），经典 2048 手感 |
| 胜利后 | 弹胜利提示，可「继续游戏」挑战更高数字；胜利只触发一次 |
| 计分 | 有。合并得分 = 合并出的新数字；localStorage 存最高分 |
| 最高分记录 | 4x4 与 5x5 分开记录（key：`best-4` / `best-5`），显示当前尺寸对应值 |
| 文件组织 | 交付物为单文件 `index.html`（内联 CSS + JS）；另附开发用测试 `tests/core.test.js` |
| 视觉风格 | 极简清新风（详见第 5 节） |
| 界面语言 | 中文 |

## 3. 架构与数据流

三层结构（单文件内分区）：

- **输入层**：键盘（方向键 + WASD）、触摸滑动、按钮
- **核心逻辑层**：纯函数，零 DOM 依赖，可单测
- **渲染层**：CSS Grid 背景格 + 绝对定位方块 + CSS transform 动画

### 3.1 状态模型

```js
state = {
  size: 4 | 5,
  board: number[][],   // 0 表示空格
  score: number,
  best: number,        // 当前尺寸对应的最高分，来自 localStorage
  won: boolean,        // 本局是否已达成 1024（防止重复触发胜利）
  over: boolean,
}
```

### 3.2 核心纯函数（`/* CORE-START */ ... /* CORE-END */` 标记包裹）

| 函数 | 职责 |
|---|---|
| `createBoard(size)` | 创建空棋盘 |
| `spawnTile(board)` | 在随机空白格生成 2(90%)/4(10%) |
| `slideLine(line)` | 单行/列移动合并，返回 `{ line, gained }` |
| `move(board, dir)` | 逐行/列调用 slideLine，返回 `{ board, moved, gained }` |
| `canMove(board)` | 是否有空格或相邻相等 |
| `isWin(board)` | 是否含 1024 |
| `isOver(board)` | `!canMove(board)` |

### 3.3 一次移动的流程

1. 输入 → `move(board, dir)`
2. `moved === false`（棋盘无变化）→ 不生成新方块、不计分，直接忽略
3. `moved === true` → 计分 → `spawnTile` → 检查 `isWin`（首次弹胜利层，可继续）→ 检查 `isOver`（失败弹层）→ 交给渲染层做动画

开局：空棋盘随机放 2 个初始方块（2048 惯例）。

### 3.4 状态机

```
playing → won弹层 →（继续游戏 | 重新开始）→ playing（继续时 won=true，不再触发）
playing → over弹层 →（再来一局）→ playing
```

弹层打开期间键盘和滑动暂停，避免误操作。

## 4. 渲染与动画

### 4.1 DOM 结构

```
.board            ← CSS Grid，size×size 个 .cell 背景格
  .cell × 16/25   ← 静态背景格
  .tile × N       ← 数字方块，绝对定位
.overlay          ← 弹层：胜利弹层含「继续游戏」/「重新开始」按钮；失败弹层含「再来一局」按钮
```

### 4.2 方块动画

- 每个方块有唯一 id，JS 维护 `tiles: [{id, row, col, value, el}]`
- **滑动**：移动后更新 row/col，CSS `transition: transform 120ms` 平滑滑到新格
- **合并**：两个方块滑到同一格 → 移除被吞并者，存活的更新数字并做 `pop` 缩放动画
- **新方块**：出生时 scale(0) → scale(1) 弹出动画
- 动画期间不锁输入：逻辑即时响应，动画异步表现，快速连击不丢输入
- 尊重 `prefers-reduced-motion`：系统开启减弱动效时动画直接跳变

### 4.3 尺寸计算

- 方块像素尺寸 = `(棋盘容器宽 − gap × (size+1)) / size`，5x5 时自动变小
- 棋盘整体尺寸 = `min(容器宽, 视口高 − 头部 − 底部)` 自适应
- 数字字号按位数自适应（2 位数最大，4 位数缩小）

### 4.4 布局

桌面居中卡片式（约 480px 内），手机竖屏单列、棋盘占满屏宽。自上而下：标题「1024」+ 分数/最高分胶囊卡 → 棋盘卡片 → 「新游戏」按钮 + 4×4/5×5 分段切换控件。

## 5. 视觉设计（极简清新风）

**设计叙事：从清晨到正午。** 方块从小到大走一段旅程：冷色调的薄荷清晨 → 逐渐转暖 → 目标 1024 是金色的「正午阳光」。

### 5.1 配色系统

方块颜色由数字本身计算，公式：

```
色相 = 155° − 12° × log₂(数字)   饱和度 ≈ 42%   明度 = 88% − 1.5% × log₂(数字)
```

| 数字 | 方块色 | 说明 |
|---|---|---|
| 2 | `#DFF2E7` | 薄荷绿（清晨） |
| 8 | `#D8EEE4` | 湖水绿 |
| 32 | `#D9EAF2` | 淡天青 |
| 128 | `#E4DCEF` | 淡薰衣草 |
| 512 | `#F7E3C6` | 杏黄 |
| **1024** | **`#FFD97A`** | **金色（正午）+ 太阳光晕** |
| ≥2048 | `#F5C558` | 深金琥珀 |

（4/16/64/256 取中间插值；实现时用 `tileColor(v)` 函数 HSL 现算，不手写 11 个色值）

- 页面底色：`#F6F8F7`（带薄荷调的近白）
- 空背景格：`#EEF2F0`；棋盘卡片：纯白、圆角 16px、柔和投影
- 文字：墨青 `#2F3B36`（非纯黑）
- 按钮/强调色：薄荷绿 `#4FAE8E`

### 5.2 字体

- 数字（标题 + 方块）：Google Fonts **Quicksand**（圆润几何体）；加载失败自动回落系统字体，离线可玩
- 中文界面文字：系统字体栈（PingFang SC / 微软雅黑 / Noto Sans SC）

### 5.3 签名元素

**1024 方块会发光**：金色底 + 柔和径向光晕 + 缓慢呼吸动画，出现时一道光扫过。冷色棋盘上唯一的一抹暖光即胜利目标本身；其余元素保持安静。

### 5.4 可访问性

- 深墨青文字在浅色块上对比度 ≥ 7:1
- 按钮有可见键盘焦点框
- 尊重 `prefers-reduced-motion`
- 胜利/失败弹层用 `aria-live` 播报

### 5.5 文案

分数 / 最高分 / 新游戏 / 继续游戏 / 再来一局
胜利：「🎉 1024！」+「继续合成更高数字，或重新开始」
失败：「没有可移动的方块了」

## 6. 边界情况（全部处理）

1. **无效移动**：移动后棋盘无变化 → 不生成新方块、不计分
2. **每格每次最多合并一次**：`[2,2,4]` 左移 → `[4,4,0]`，不能是 `[8,0,0]`
3. **合并方向优先**：`[2,2,2,2]` 左移 → `[4,4,0,0]`
4. **先滑后并**：`[2,0,2]` 左移 → `[4,0,0]`
5. 得分只算合并出的新数字，滑动的方块不得分
6. 新方块只在空白格生成
7. 胜利只触发一次，继续游戏后不再弹
8. 死局判定：无空格且无任意相邻相等 → 失败弹层
9. localStorage 隐私模式异常 → try/catch 静默降级（最高分只存活于本局）
10. 弹层打开期间暂停输入；切换 4x4/5x5 即新开一局
11. 快速连击不丢输入；移动端禁双击缩放（`touch-action: none`）、禁长按选中（`user-select: none`）
12. 一次触摸序列只触发一次移动（阈值 ~30px，取 |dx|/|dy| 较大方向）

## 7. 测试策略（TDD）

- 核心逻辑为纯函数，以 `/* CORE-START */ /* CORE-END */` 标记包裹，与 DOM 层分离
- `tests/core.test.js`：Node 直接运行（`node tests/core.test.js`），无需浏览器、零依赖。读取 index.html → 正则提取 CORE 段 → eval → 断言
- 用例覆盖：
  - `slideLine`：合并规则（第 6 节第 2/3/4 条）、得分计算
  - `move`：四个方向、`moved` 判定
  - `spawnTile`：只落空白格、2/4 比例 ≈ 9:1（统计 1000 次验证）
  - `canMove` / `isWin` / `isOver`
  - 完整回合集成：移动 → 合并 → 计分 → 生成 → 判胜负
- 手动验收清单（浏览器打开 index.html）：
  - 键盘四方向 + WASD 可玩，方向键不滚动页面
  - 手机模拟器/真机滑动可玩，一次滑动只触发一次移动
  - 滑动/合并/弹出动画流畅
  - 拼出 1024 弹胜利层，继续后不再弹
  - 死局弹失败层
  - 切换 4x4/5x5 重开新局，最高分分开记录
  - 刷新页面最高分保留
  - 系统开启「减弱动态效果」时动画跳变
